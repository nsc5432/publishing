# API 명세 델타 — 병합 완료

이 문서는 1단계(사용자 시뮬레이션 리뉴얼) 산출물이었다. 리뉴얼 3탭 화면이 요구하는 데이터 항목을 당시 [`API_SPEC.md`](API_SPEC.md) 6장과 대조해 정리하고, 화면에서 확정할 수 없는 것을 **결정 필요**로 표시한 목록이다.

**내용은 3단계(조회)와 4단계(저장·실행)를 거쳐 [`API_SPEC.md`](API_SPEC.md) 본문으로 전부 병합됐다.** 계약을 볼 때는 본문을 본다. 이 파일은 다른 문서의 참조를 깨지 않으려고 남겨 두었고, 아래 표가 델타 항목의 최종 처리 상태다.

- 원문 델타의 서술은 [`docs/db/04-screen-table-mapping.md`](../../../../docs/db/04-screen-table-mapping.md) 가 항목별로 다시 다룬다 (2단계 산출물).
- 결정 근거는 [`docs/db/06-decisions.md`](../../../../docs/db/06-decisions.md)(3단계) · [`docs/db/07-save-decisions.md`](../../../../docs/db/07-save-decisions.md)(4단계).

## 1. 탭 구조 변경 (5탭 → 3탭)

| 델타 항목 | 처리 | 반영처 |
| --- | --- | --- |
| `6.4` 셀프체크인/백드롭 → `6.3` 흡수 | **완료** — 조회·저장 모두 체크인 카운터 안으로. 엔드포인트·타입 제거 | `API_SPEC.md` 6.3 / 6.4, D20 |
| `6.6` 보안 검색대 → `6.5` 흡수 | **완료** — 〃 출국장 안으로 | `API_SPEC.md` 6.5 / 6.6, D20 |
| 조회 단위: 아일랜드 1개분 → 터미널 1개분 | **완료** — `island` 파라미터는 무시되고 항상 터미널 전체를 내려준다. 별도 조회를 추가하지 않았다 | `API_SPEC.md` 6.3 |

## 2. 체크인 카운터 탭

| 델타 항목 | 처리 | 반영처 |
| --- | --- | --- |
| 2.1 `islandList[].boothCnt` / `oprTimeList` / `peakCounterCnt` | **완료** — 조회는 배정 테이블의 운영시간을 시간축으로 펼쳐 계산 | D2, `API_SPEC.md` 6.3 |
| 2.1 `boothCnt` 가 고정값인가 편집값인가 | **완료** — 편집값. 저장 시 `boothList` 길이를 쓴다 (화면 계산식과 동일) | D10, `API_SPEC.md` 6.3 저장 |
| 2.2 대기인원 꺾은선의 출처 | **완료** — 직전 시뮬레이션 결과(`TN_PM_SMLT_RSLT_DTL`). 미수행이면 24개 전부 `0` | D4 |
| 2.3 KPI 4종 | **완료** — 〃. `p95WaitMin` 은 근사, `utilRate` 는 정의를 새로 만들었다 | D4·D5·D6 |
| 2.4 `alnCdList`(배정 가능 항공사) | **완료** — `TN_CA_ALN_PGE` 에서 뽑는다 | `API_SPEC.md` 6.3 |

| 2.5 아일랜드별 `kioskCnt` / `bagDropCnt` | **완료** — 조회·저장 모두 아일랜드 단위 | D10 |
| 2.5 기기별 운영시간(구 `deviceList[].oprTimeList`) | **부분** — 저장하지 않기로 했다. 기존 데이터는 지우지 않는다. **현업 확인 잔여** | D20 |
| 2.6 `saveSlfchknInfo` 폐기 여부 | **완료** — 폐기 | D20 |
| 2.6 신규 아일랜드 식별 | **완료** — 아일랜드 문자 1자가 그대로 키다 (`SMLT_ID`+`TMNL_ID`+`CHKN_ISL_CD`). 별도 일련번호를 두지 않았다 | D10 |

## 3. 출국장 탭

| 델타 항목 | 처리 | 반영처 |
| --- | --- | --- |
| 3.1 `depList[].scCnt` · `peakScCnt` | **완료** — 조회는 `..._SCRTY_CNTRL_ATRB.FCLTY_CNT`, 저장은 신규 테이블 | D2, D10 |
| 3.2 `planList` 분 단위 유지 여부 | **완료** — 분을 버리고 시(`0`~`24`) 정수로 바꿨다 | `API_SPEC.md` 6.5 |
| 3.2 구간별 대수를 담을 구조 (G7) | **완료** — `TN_PM_SMLT_SC_PLAN` 신설. **다구간 저장이 가능해졌다** (조회는 아직 구간 1개) | D2 → D10 |
| 3.3 `scCnt` = `normalCnt` + `smartPassCnt` 인가 | **부분** — 컬럼 3개를 독립으로 두어 어느 쪽이든 담을 수 있게 했다. **관계 정의는 현업 확인 잔여** | D10 |
| 3.4 `saveScPlanInfo` 를 합칠지 | **완료** — `saveDepInfo` 에 흡수. 테이블 3개를 한 트랜잭션으로 쓴다 | D20 |
| `depList[].oprYn` 의 저장처 | **완료** — 마스터 `USE_YN` 이 아니라 `TN_PM_SMLT_USER_DEP.OPER_YN` | D10 |
