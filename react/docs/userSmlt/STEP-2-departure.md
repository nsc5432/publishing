# STEP-2 · 출국장 (DepartureTab)

> 설계서: [출국장 — 차트 + 검색대 격자](https://claude.ai/code/artifact/6feafa19-c268-4199-92ce-24eb630ed01c)
> 선행: **[STEP-0 (공통)](./STEP-0-common.md) 이 끝나 있어야 한다.** `BlockChartProps`(`stackMode` · `gridLeft` · `selected`) · `CountStepper variant` · 좌표 토큰(`--gut/--col/--rgt`)은 여기서 다시 정의하지 않는다.
> 대상: `react/src/modules/pm/pages/userSmlt/tabs/departure/`

## 한 줄 요약

위는 출국장이 **언제** 열리는지를 블럭과 대기인원 꺾은선으로 말하고, 아래는 그 출국장에 검색대가 **몇 대** 붙는지를 격자의 숫자로 말한다. 두 표면이 같은 시간 좌표 위에 세로로 정렬되어, 위에서 고른 출국장이 아래에서 그대로 한 줄이 된다.

## 왜 바꾸는가

`DepartureGate` 에는 성격이 다른 두 값이 나란히 있다.

- `ranges` — 출국장의 **운영시간**
- `plans` — 그 안에서 시간대별 **검색대 대수**

지금 화면은 이 둘을 차트 두 개로 나눠 놓았는데, **아래 보조 차트가 `gate.scCnt`(피크 고정값)만 읽는 바람에 정작 시간대별 변화는 어느 쪽에도 그려지지 않는다.**

이 설계는 두 값을 두 표면에 하나씩 맡긴다.

| 표면 | 맡는 값 | 묻는 질문 | 세로 단위 |
|---|---|---|---|
| 위 — 차트 | `ranges` · `off` | 몇 개 출국장이 언제 열려 있나 · 대기와 맞나 | 쌓인 블럭 수 = 운영 출국장 수 |
| 아래 — 격자 | `plans` | 어느 출국장이 몇 시에 몇 대인가 | **고정 N줄 = 출국장 전체** |

겹치는 것이 없으므로 어느 쪽을 보고 무엇을 고쳐야 하는지가 헷갈리지 않는다.

## 스텝 1 · ScGrid 를 읽기 전용으로 붙인다

**이 단계만으로 "어느 출국장이 몇 시에 몇 대인가"가 이미 답을 얻는다.** 보조 차트는 아직 그대로 둔다.

신규: `tabs/departure/components/ScGrid.tsx` — **DOM 격자다. ECharts 를 쓰지 않는다.**

### 1-1. 줄은 고정이다

운영 중인 것만 그리지 않는다. **출국장 6개가 언제나 6줄**로 있고, 그 시간에 닫혀 있으면 빗금 칸이 된다. 줄이 사라지지 않으므로 눈이 세로로 훑을 때 자리가 흔들리지 않고, 미운영 출국장도 화면에서 없어지지 않는다.

체크인 설계에서 도크 상단 칩이 하던 일을 여기서는 격자가 맡으므로, **칩 줄이 따로 필요 없다.**

### 1-2. 칸의 세 가지 상태

| 상태 | 조건 | 그리기 |
|---|---|---|
| **운영 · N대** | `ranges` 안 · `count > 0` | 숫자가 값이고, **하나의 순차 램프**(옅음 → 진함)로 농도를 입힌다 |
| **운영 · 0대** | `ranges` 안 · `count === 0` | 붉은 `0` — 문이 열렸는데 검색대가 없다. 눈에 걸리게 둔다 |
| **미운영** | `ranges` 밖 | 빗금. 값을 넣을 수 없다 |

> **값을 출국장 색으로 칠하지 않는 이유**
> 서로 다른 색의 4와 5는 눈으로 비교되지 않는다. 값은 **하나의 순차 램프**로 칠해야 격자 전체가 히트맵으로 읽힌다.
> 출국장 정체성은 **왼쪽 라벨의 색 막대**가 맡는다 — 위 차트 블럭 색과 같다.

### 1-3. 줄 밖의 세 자리

- **왼쪽 44px (`--gut`)** — 색 막대 + `3번`. 클릭하면 그 출국장 속성 편집이 열린다(스텝 4)
- **오른쪽 40px (`--rgt`)** — 그 출국장의 **피크 대수**. 세로로 훑으면 출국장별 보유 규모가 한 열로 읽힌다
- **맨 아랫줄** — 시간별 합계. **농도까지 입혀** 그 줄 자체가 24칸짜리 막대그래프로 읽히게 한다. 정점 칸은 강조하고, 오른쪽 끝이 총 피크

> 앞 시안 검토에서 격자의 약점으로 꼽혔던 것이 "총 공급의 형태가 안 보인다"였다. 농도를 입힌 합계 줄이 바로 위 차트의 대기 꺾은선과 세로로 맞물리므로 **별도 곡선을 하나 더 그릴 필요가 없다.**

### 1-5. `tabs/departure/view.ts` — 24칸으로 펴는 함수

`DepartureTab.tsx` 안에 있는 `scByHour()` 를 뷰 계층으로 옮기고 24칸 배열로 바꾼다.

```ts
/** 운영계획을 24칸 배열로 편다 — 격자 셀 / 합계 / 피크가 모두 이 배열을 읽는다 */
export function toHourArray(gate: DepartureGate): number[] {
    const byHour = Array<number>(24).fill(0);
    gate.plans.forEach((plan) => {
        for (let h = plan.startHour; h < plan.endHour; h += 1) byHour[h] = plan.count;
    });

    return byHour;
}
```

## 스텝 2 · 좌표를 맞추고 보조 차트를 걷어낸다

두 표면이 한 화면으로 읽히려면 **시간 칸이 픽셀 단위로 맞아야** 한다. 08시 블럭 바로 아래에 08시 셀이 오지 않으면 합쳐 놓은 뜻이 없다.

### 2-1. 주 차트 값

```tsx
<BlockChart
    items={toGateItems(gates)}   // 미운영 포함 — stackMode="fixed" 가 자리를 지킨다
    title="시간대별 운영 출국장"
    unit="1블럭 = 출국장 1개"

    rowH={18}                    // 22 → 18
    gridLeft={44}                // 격자 라벨 폭과 맞춘다
    stackMode="fixed"            // 출국장 번호 오름차순 고정
    blockFontSize={13}
    line={panelData.wait}

```

**쌓는 순서가 이 스텝의 핵심이다.** 지금은 열려 있는 것부터 차례로 쌓기 때문에 시간마다 같은 출국장이 다른 높이에 나타난다. 아래 격자는 줄 순서가 고정인데 위가 흔들리면 눈이 두 표면을 잇지 못한다. **출국장 번호 오름차순으로 고정**하고, 그 시간에 닫힌 출국장 자리는 비워 둔다.

블럭 안에는 **대수를 넣지 않는다** — 그건 아래 격자의 일이다. 툴팁은 `3번 출국장 · 07~11시 · 검색대 4대`.

## 스텝 3 · 격자를 입력기로 만든다

격자는 조회면서 동시에 입력기다. **여러 출국장 × 여러 시간을 사각형으로 끌어 한 번에 같은 대수로 맞추는 조작**이 여기서 성립한다 — 펼 대상이 6개뿐이라 줄이 고정돼 있기 때문이다. (체크인 카운터는 스택이 계단 모양이라 이게 안 된다 — [STEP-1 스텝 4-3](./STEP-1-checkin-counter.md) 참고)

### 3-1. 조작

| 조작 | 결과 | 비고 |
|---|---|---|
| 칸 드래그 | 사각형 안의 칸이 모두 선택된다 | 미운영(빗금) 칸은 선택에서 **자동으로 빠진다** |
| 팝오버 스테퍼 | 선택된 칸이 전부 그 대수가 된다 | 보유 합계를 넘으면 붉게 경고하고 `적용` 이 잠긴다 |
| `Esc` | 선택 해제 | |
| 줄 라벨 클릭 | 그 출국장의 속성 편집이 열린다 | `DetailDrawer` 재사용 (스텝 4) |
| 위 블럭 클릭 | 아래 같은 줄이 켜진다 | 양방향은 스텝 5 |
| 균등 배치 | 보유 검색대를 운영시간 전체에 같은 대수로 편다 | 선택이 있으면 선택 범위에만, 없으면 전체에 (스텝 5) |

팝오버는 **선택 영역 아래에 붙는다.** `CountStepper variant="inline"` 을 쓴다(STEP-0 §5).

### 3-2. 편집 상태 전환

`DepartureTab.tsx` 의 편집 상태에 24칸 배열을 더한다.

```ts
type EditState = Record<TerminalKind, DepartureGate[]>;
/** 출국장 번호 → 24칸. 조회 결과가 들어올 때 toHourArray() 로 채운다 */
```

`plans` 를 손으로 쪼개고 합치는 일이 사라지므로 `+ 구간 추가` 버튼과 `addPlan()` · `planSeq` 가 필요 없어진다.

### 3-3. 저장 — 24칸 배열을 `ScRange[]` 로 되묶는다

`tabs/departure/view.ts` 에 추가.

```ts
/** 격자 24칸 → ScRange[] · 같은 값이 이어지는 동안 한 구간으로 묶는다 */
export function toPlans(byHour: number[], prev: ScRange[]): ScRange[] {
    const out: ScRange[] = [];
    let h = 0;

    while (h < 24) {
        const count = byHour[h];
        // 0 은 구간을 만들지 않는다 — 운영시간(ranges)은 위 차트가 따로 관리한다
        if (count === 0) { h += 1; continue; }

        let end = h + 1;
        while (end < 24 && byHour[end] === count) end += 1;

        // 시작 시각이 같은 기존 행이 있으면 그 id 를 물려받아 planSn 을 지킨다
        const kept = prev.find((plan) => plan.startHour === h);
        out.push({ id: kept?.id ?? `new-${++seq}`, startHour: h, endHour: end, count });
        h = end;
    }

    return out;
}
```

> ### ⚠️ `planSn` 을 잃지 않도록
> `view.ts` 의 `toPlanId()` 가 서버 일련번호를 화면 키(`g{depNum}-r{planSn}`)에 실어 두고 있다.
> 구간을 다시 묶을 때 **시작 시각이 같은 기존 행의 id 를 물려받으면** 수정으로 처리되고, 물려받을 것이 없을 때만 신규(`planSn = 0`)로 나간다.
> **`toSaveReq()` 는 손대지 않아도 된다** — `gate.plans` 를 채워 넣기 전에 `toPlans()` 를 한 번 돌리면 끝이다.

> ### ⚠️ 확인 필요 ③ — `ranges` 안인데 `plans` 가 없는 시간
> 서버 데이터에 그런 시간이 존재할 수 있다. 이 설계는 그것을 **운영 · 0대** 상태로 그려 붉게 남긴다(스텝 1-2).
> 서버가 두 값을 **항상 함께 채우는 것이 보장된다면**, 이 상태는 편집 중에만 잠깐 나타나는 것이 되고 저장 시 검증으로 막을 수 있다. 보장 여부를 확인해 정한다.

삭제 대상:

- `tabs/departure/components/ScRangeTable.tsx` (파일째)

## 스텝 5 · 양방향 선택과 균등 배치 — 선택사항

**없어도 스텝 4 까지로 편집이 완결된다.**

### 5-1. 양방향 선택

위 블럭을 고르면 아래 같은 줄이 켜지고 그 운영 구간이 선택된다. 격자에서 고르면 위 블럭도 함께 강조된다. `BlockChart.selected`(STEP-0 §2)와 `ScGrid.selected` 를 탭의 같은 상태에 묶으면 된다.

### 5-2. 균등 배치 버튼 통합

지금 `균등 배치` 버튼이 **차트 헤드와 드로어 두 곳**에 있고 하는 일이 적혀 있지 않다(둘 다 `console.log` 만 한다). **격자 위 한 곳으로 합치고** 뜻을 고정한다.

> 보유 검색대를 운영시간 전체에 같은 대수로 편다. **선택이 있으면 선택 범위에만, 없으면 전체에.** 시간대별 조정은 그 뒤에 손으로 한다.

`.bchart__act--even`(차트 헤드) 과 `.btn--even`(드로어 헤더) 중 남는 한쪽의 CSS 를 지운다.

## 세로 예산

패널 하나에 쓸 수 있는 세로를 약 **420px** 로 잡는다(`100vh` 껍데기 안, 요약줄 · KPI · 저장 버튼을 뺀 나머지).

| 구성 | 계산 | T1 | T2 |
|---|---|---|---|
| 차트 헤드 | 제목 + 범례 칩 | 26 | 26 |
| 차트 플롯 | `levels × rowH 18 + 상하 여백 25` | 133 | 61 |
| 시간 축 | `00 02 … 22` | 20 | 20 |
| 격자 머리 | 구분선 + 제목줄 | 31 | 31 |
| 격자 본문 | `출국장 수 × 21` | 126 | 42 |
| 합계 줄 | `여백 7 + 19` | 26 | 26 |
| 패널 여백 | 상하 패딩 | 3 | 3 |
| **합계** | 가용 420px 대비 | **365** | **209** |

여백 25 는 `BlockChart.tsx` 의 `PAD_TOP 18 + PAD_BOTTOM 7` 과 같다. 두 표면을 합쳐도 예산 안에 들어온다 — 지금의 주 차트 + 보조 차트 조합과 비슷한 크기다.

앞 시안(398px)에서 줄인 것: 미운영 출국장을 별도 줄로 더하지 않고(6줄 안에 이미 있다) · 셀 높이 22 → 20(줄 간격 포함 21) · 차트 `rowH` 22 → 18 · 대기 스파크 띠 제거(위 차트 꺾은선이 이미 그 일을 한다).

**T2 는 패널 높이를 T1 에 맞추지 말고 위로 정렬하고 아래를 비운다.** 억지로 늘리면 2줄짜리 격자가 이상하게 성겨 보인다.
