# 체크인 공용 Queue 단일 결과 구현 계획

작성일: 2026-09-04 · 대상: `java/cast`, `java/mapper`, `react/src`

---

## 0. 목표와 확정사항

CAST가 내려주는 유인 체크인카운터 부스별 결과를 계산 원천으로만 보존하고, 업무 API와 화면에는
아일랜드 단위 공용 `Queue` 결과만 제공한다.

- Queue 대상은 유인카운터 `CC`만이다. `CK`(셀프체크인)와 `SBD`(셀프백드롭)는 자원 정보로만 남기고
  Queue 대기인원·혼잡·추천 계산에서는 제외한다.
- `QueueLength_Current`는 중복되지 않은 부스별 독립 Queue 값이다.
- `FinishedClients_Abs`는 누적값이 아니라 구간 처리인원이다.
- 사용자에게 부스 집계와 Queue 추정을 함께 보여주지 않는다. 화면 표기는 모두 `Queue`로 통일한다.
- 적용 범위는 대시보드 체크인 카드, 터미널맵 체크인 마커·팝업, 체크인 상세 화면이다.
- 혼잡등급은 기존과 같은 대기인원 기준을 사용한다.
- 필요 부스 수는 향후 Queue 피크를 `NORMAL` 등급 상한 이하로 만드는 **총 소요 부스 수**다.
- Queue는 조회 시 계산하며 별도 결과 테이블이나 DDL은 추가하지 않는다.

`java/`는 백엔드 참조 사본이어서 이 저장소에서 컴파일할 수 없다. Java 변경은 실제 백엔드 저장소에
옮긴 뒤 컴파일·테스트해야 한다.

## 1. 현재 구현의 문제

현재 체크인 관련 화면은 같은 원천을 서로 다른 방식으로 집계한다.

- `CastMapMapper.retrieveMapRsltDayList`는 30분 구간에서 대기인원 `MAX`, 처리인원 `SUM`, 대기·처리시간
  단순 `AVG`를 사용한다.
- `SmltUtils.foldByTimeAndUnitCd`는 `CC`, `CK`, `SBD`를 아일랜드로 다시 합치면서 대기인원과 시간을
  `MAX`, 처리인원을 `SUM`한다.
- `CastSmltMapper.retrieveWaitPsgList`는 한 시간 안의 모든 순간 대기인원을 `SUM`한다. 순간 재고량인
  대기인원이 시간 내에서 중복 합산된다.
- `retrieveSmltKpiRaw`의 P95는 여객 대기시간 P95가 아니라 결과 행별 평균대기시간의 P95다.
- 대시보드, 터미널맵, 체크인 상세 화면이 서로 다른 조회·집계 경로를 사용하므로 같은 시각의 체크인
  지표가 달라질 수 있다.

공용 `CastMapMapper.retrieveMapRsltDayList`는 출국장 등 다른 화면도 사용하므로 Queue 구현을 위해
수정하지 않는다. 체크인 전용 원천 조회와 공용 Queue 계산기를 추가한다.

## 2. 백엔드 설계

### 2.1 체크인 전용 원천 조회

`CastChknMapper`에 Queue 계산 전용 조회를 추가한다.

- 조건: `SMLT_ID`, 터미널, `UP_PSG_FCLT_CD = 'CC'`, 시설 `USE_YN = 'Y'`
- 시간은 30분으로 미리 자르지 않고 정확한 `SMLT_ACTL_DT`를 반환한다.
- 행 단위는 시각 + `PSG_FCLT_CD`다.
- 반환값: `SMLT_ACTL_DT`, 시설코드, 아일랜드, `WTNG_PSG_CNT`, `TRNST_PSG_CNT`,
  `AVG_WTNG_HR`, `AVG_PRCS_HR`
- 아일랜드는 현행 시설코드 규칙을 사용하되 결과 DTO에 명시적으로 담아 이후 계산에서 문자열을 다시
  자르지 않는다.

부스 운영 여부는 실제 배정 시간 구간을 기준으로 판정한다. 배정 시간 밖인데 해당 부스에 대기 또는
처리 결과가 있으면 운영 부스로 포함하고 데이터 불일치를 서버 로그에 남긴다.

### 2.2 공용 Queue 계산기

상태 없는 순수 계산기 `ChknQueueCalculator`와 조회·기준정보 조립을 담당하는 서비스를 분리한다.
대시보드, 터미널맵, 체크인 상세 서비스가 같은 계산 결과를 재사용해야 한다.

아일랜드별 원천 구간 `t`에서 다음 값을 만든다.

```text
observedQueue[t] = SUM(부스별 WTNG_PSG_CNT)
observedProcessed[t] = SUM(부스별 FinishedClients_Abs)
arrivals[t] = MAX(0, observedQueue[t] - observedQueue[t-1] + observedProcessed[t])
```

- 첫 구간의 `observedQueue[t-1]`은 0으로 보고 `observedQueue + observedProcessed`를 유입으로 본다.
- 음수 유입은 0으로 보정하고 보정 건수·원천값을 로그에 남긴다.
- 부스별 평균 처리시간이 양수이면 `구간 초 / 평균 처리시간`으로 처리용량을 계산한다.
- 처리시간 fallback 순서는 동일 아일랜드 최근 60분 처리인원 가중평균 → 당일 터미널 CC 처리인원
  가중평균 → 관측 처리량이다. 모두 없으면 처리용량을 0으로 두고 로그를 남긴다.
- 소수 처리용량은 버리지 않고 다음 분으로 이월한다.

각 원천 구간의 유입과 처리용량을 1분 단위로 균등 배분하고 FIFO 코호트로 계산한다.

```text
processed[min] = MIN(queueBeforeService[min], capacity[min])
queueEnd[min] = queueBeforeService[min] - processed[min]
wait[min] = 서비스 시작 분 - 코호트 유입 분
```

정수 유입의 나머지는 구간 앞쪽 분부터 1명씩 배분한다. 처리용량은 실수 누적 후 정수부만 처리해 실행할
때마다 같은 결과가 나오게 한다.

### 2.3 30분·1시간 집계

화면용 30분 슬롯은 분 단위 결과를 다음과 같이 집계한다.

- 현재 Queue: 구간 마지막 분의 Queue
- 평균 Queue: 분별 Queue의 산술평균
- 최대 Queue: 분별 Queue의 최댓값
- 평균 대기시간: 해당 구간 처리 여객의 가중평균 대기시간
- 처리인원: 구간 처리인원 합계
- 평균 처리시간: 처리인원 가중평균
- 처리용량 사용률: `처리인원 / 처리용량 × 100`, 0~100 정수
- 운영 부스: 구간 내 실제 운영 부스 수. 변동 시 구간 마지막 값을 화면의 현재값으로 사용한다.

기존 1시간 `rsrcList`를 유지해야 하는 호환 경로에서는 대기인원을 합산하지 않는다. 매시 마지막 Queue를
사용하고 처리인원만 두 30분 슬롯을 합산한다.

### 2.4 혼잡등급과 부스 추천

대시보드 안에 갇혀 있는 혼잡등급 기준정보 조립을 공용 도메인으로 분리한다.

- 체크인 시설그룹의 등급 범위와 `NORMAL` 상한은 기존 DB 기준정보에서 읽는다.
- 하드코딩된 220명은 fallback으로 사용하지 않는다. 기준정보가 없거나 겹치면 기존 대시보드와 동일하게
  조회 실패로 처리한다.
- 슬롯의 혼잡등급은 현재 Queue로 결정한다.
- 부스 추천은 기존 `FcltRecommendationCalculator`에 공용 Queue 궤적을 전달해 계산한다.
- 추천 구간은 선택 시각부터 향후 60분이며, 피크를 `NORMAL` 상한 이하로 만드는 수량을 구한다.
- `reqCnt`는 추가 수량이 아니라 현재 운영분을 포함한 총 소요 부스 수다.
- 혼잡 해소 예상시간은 추천 부스를 적용했을 때 Queue가 처음 `NORMAL` 이하가 되는 경과 분이다.
- 운영 부스 또는 서비스율이 0이라 계산할 수 없으면 추천값을 `null`로 내려 화면에서 `-`로 표시한다.

## 3. API 계약

기존 DTO 필드는 삭제하거나 리네임하지 않는다. 체크인 응답에서 기존 필드는 다음 Queue 의미를 갖는다.

| 필드 | Queue 의미 |
|---|---|
| `wtngPsgCnt` | 슬롯 마지막의 공용 Queue 인원 |
| `wtngHr` | FIFO 평균 대기시간(초) |
| `prcsPsgCnt` | 공용 Queue 구간 처리인원 |
| `prcsHr` | 처리인원 가중 평균 처리시간(초) |
| `prcsRate` | 처리용량 사용률(%) |
| `waitMaxCnt` | 당일 공용 Queue 최댓값 |
| `kpi.avgWaitMin` | 당일 처리여객 가중 평균대기(분) |
| `kpi.p95WaitMin` | FIFO 코호트 기준 근사 P95(분), 화면에는 노출하지 않음 |
| `kpi.maxQueuePsgCnt` | 당일 최대 Queue 인원 |
| `kpi.utilRate` | 당일 처리용량 사용률(%) |

`MapChknRsltDto`와 대응하는 `api.types.ts` 인터페이스에 다음 필드를 추가한다.

| 필드 | 타입 | 의미 |
|---|---|---|
| `avgQueuePsgCnt` | `number` | 30분 평균 Queue 인원 |
| `maxQueuePsgCnt` | `number` | 30분 최대 Queue 인원 |
| `oprBoothCnt` | `number` | 슬롯 마지막 운영 부스 수 |
| `reqCnt` | `number \| null` | NORMAL 이하를 위한 총 소요 부스 수 |
| `cgnClearMin` | `number \| null` | 추천 적용 후 NORMAL 도달 예상 분 |

알림에서 같은 정보를 쓰도록 `MapNoticeItemDto`에도 `reqCnt`, `cgnClearMin`을 추가한다. 새 필드명과 기존
`reqCnt` 의미는 추가 후 고정한다.

## 4. 화면별 적용

### 4.1 체크인 상세

- 상단 KPI는 평균 대기, 최대 Queue와 피크 시각, 총 처리인원, 처리용량 사용률로 구성한다.
- 기존 P95 카드는 제거하되 API 필드는 호환을 위해 유지한다.
- 차트는 30분 단위 운영 부스 막대와 Queue 인원 선으로 구성한다. 툴팁에 평균대기, 처리인원,
  처리용량 사용률을 표시한다.
- 아일랜드 칩은 현재 Queue를 주 값으로, `운영 부스 수 · 평균대기`를 보조 값으로 표시한다.
- 표 컬럼은 아일랜드, 상태, 운영 부스, 현재 Queue, 평균/최대 Queue, 평균대기, 30분 처리인원,
  사용률, NORMAL 도달 예상, 총 소요 부스, 항공사 순서로 구성한다.
- `CK`, `SBD`, 운영시간 상세는 표에서 제거하고 상단 자원 요약 또는 기존 상세정보에만 남긴다.
- 혼잡 알림은 `BUSY` 이상 아일랜드를 Queue 내림차순으로 정렬하고 총 소요 부스와 예상 해소시간을
  안내한다.

기존 `className` 문자열은 변경하지 않는다. 필요한 스타일은 새 클래스로 추가하며, 수정하는 파일에
남아 있는 동작 설명용 주석과 요약 doc 주석은 프로젝트 규칙에 따라 함께 정리한다.

### 4.2 대시보드

- 체크인 시설 카드의 대기·처리·혼잡 값은 `CC` 공용 Queue 결과만 사용한다.
- 카드 추천의 `reqCnt`, `needAssignYn`, 혼잡 해소시간은 공용 Queue 궤적으로 다시 계산한다.
- 키오스크와 셀프백드롭 수량은 자원 현황에는 유지하지만 Queue와 추천에는 포함하지 않는다.

### 4.3 터미널맵

- 체크인 아일랜드 마커 색상, 팝업 대기인원·시간·처리인원, 상단 혼잡 알림은 같은 Queue 슬롯을 사용한다.
- 같은 `smltId`, 터미널, `hhmm`, 아일랜드에서 체크인 상세와 값·등급이 반드시 일치해야 한다.
- 출국장과 다른 시설의 기존 `CastMapMapper` 집계는 변경하지 않는다.

## 5. 검증

### 5.1 Queue 계산 사례

- 여러 부스 Queue가 한 부스에 치우친 경우 공용 Queue에서 빈 부스 용량을 사용한다.
- 균등 부스, 무유입, 무처리, Queue 증가, Queue 완전 해소를 검증한다.
- 첫 구간, 자정 경계, 30분·1시간 롤업을 검증한다.
- 부스 개폐 시점과 배정 외 처리 결과를 검증한다.
- 평균 처리시간 누락의 각 fallback과 모든 fallback 실패를 검증한다.
- 소수 처리용량 이월 결과가 반복 실행에서도 동일한지 검증한다.
- 대기인원 역산이 음수가 되는 경우 0 보정과 로그를 검증한다.

### 5.2 등급·추천 사례

- Queue가 NORMAL 이하인 경우 `reqCnt`가 현재 운영 부스 수인지 확인한다.
- NORMAL 초과 시 총 소요 부스 수와 예상 NORMAL 도달시간을 확인한다.
- 운영 부스 0, 서비스율 없음, 60분 궤적 부족 시 추천값이 `null`인지 확인한다.
- 물리적 보유 부스보다 큰 소요량도 계산값을 숨기거나 임의로 자르지 않는다.

### 5.3 화면·계약 검증

- 동일 조건에서 대시보드, 터미널맵, 체크인 상세의 Queue와 혼잡등급이 일치해야 한다.
- T1/T2, 빈 아일랜드, 미운영 아일랜드, 데이터 누락, 24:00 슬롯을 확인한다.
- 목업을 Queue 궤적과 추천값에 맞게 갱신하고 차트·표·타임라인 전환을 육안 확인한다.
- React에서 `npx tsc -b`, `npx eslint .`, `npm run build`를 실행한다.
- 실제 백엔드 저장소에서 Queue 계산기 단위 테스트와 Java 컴파일을 수행한다.

## 6. 구현 순서

1. 체크인 전용 원천 DTO·mapper 조회를 추가한다.
2. 공용 혼잡등급 기준정보와 Queue 계산기를 구현하고 고정 사례로 산식을 검증한다.
3. 체크인 상세 서비스가 기존 집계를 제거하고 Queue 결과를 반환하도록 바꾼다.
4. 터미널맵 체크인 경로를 같은 Queue 결과로 교체한다.
5. 대시보드 체크인 카드와 기존 추천 계산기를 Queue 궤적에 연결한다.
6. API 타입·목업·체크인 상세 UI를 Queue 중심으로 변경한다.
7. 세 화면 값 일치, 타입체크, lint, build, 실제 백엔드 테스트를 수행한다.
