## 1. 사용자 확정 범위와 설계 제안

사용자 확정 범위:

- 체크인카운터와 출국장은 같은 결과 테이블에서 관리한다.
- 두 시설 모두 10분 단위로 저장한다.
- `QUEUE_CALC_SN` 같은 별도 연결 ID 대신 기존 `SMLT_ID`로 연결한다.
- 기존 설정 PK에 맞춰 `SMLT_MDL_SN`을 함께 사용한다.
- 새 테이블·컬럼명은 `표준단어.txt`를 우선 적용한다. 기존 API 필드·enum은 변경하지 않는다.
- 별도 계산 상태 테이블은 두지 않는다. 공통 결과 테이블 하나로 관리한다.
- 대시보드의 큐 계산 중간 단계를 줄이고 사전 저장된 결과를 조회하는 방향으로 전환한다.
- 기본 통계만 저장하며 혼잡등급·추천 수량·혼잡해소는 조회 시 계산한다.
- 혼잡등급과 예측에는 조회 시점의 최신 기준표를 적용한다.
- 저장 결과가 없거나 불완전하면 기존 Java 계산으로 보완한다.
- 체크인 추천·해소는 10분 통계로 근사하고 기존 분별 FIFO 예측값과의 차이를 허용한다.
- 동일 평가 경로를 카드·맵·체크인 상세·혼잡해소 팝업에 함께 적용하여 화면 간 값 일치를 유지한다.
- 차트·PRIME TIME은 기존 경로를 유지한다. 차트용 추가 합성 통계는 이번 테이블에 저장하지 않는다.
- 일일·사용자 모두 새 시뮬레이션 실행에는 새 `SMLT_ID`를 사용한다.
  신규 실행 결과를 수신한 뒤 해당 ID의 큐를 한 번 계산·저장한다.

구현 기본 방식:

- 체크인 내부 FIFO는 1분 계산을 유지하고, 결과를 10분으로 집계한다.
- 원천 수신 성공을 보존한 뒤 파생 결과를 별도 트랜잭션으로 생성한다.
- 조회 시 분별 처리 이력과 잔여 도착군은 10분 통계에서 근사하며, 이를 위한 보조 테이블은 추가하지 않는다.
- CHKN 일일 95분위 등 이번에 전환하지 않는 통계는 기존 계산을 유지한다.

새 세션에서 이 문서 기반 코딩을 요청하면 위 기본 방식과 §12를 기준으로 구현한다.
이 문서 작성만으로 실제 DB 적용·배포·커밋·푸시까지 승인된 것은 아니다.

## 2. 테이블과 관계

| 테이블 | 논리명 | 역할 |
|---|---|---|
| `TN_PM_SMLT_STNG` | 시뮬레이션설정 | 기존 실행·모델 부모 |
| `TN_PM_SMLT_RSLT_DTL` | 시뮬레이션결과상세 | 기존 부스·검색대별 CAST 원천 |
| `TN_PM_SMLT_FCLT_WTNG_RSLT` | 시뮬레이션시설대기결과 | 시설별 10분 파생 결과 |

결과 테이블 PK:

```text
(SMLT_ID, SMLT_MDL_SN, TMNL_ID, FCLT_TYPE_CD, FCLT_UNIT_CD, SEC_BGNG_DT)
```

결과 저장 단위:

```text
(SMLT_ID, SMLT_MDL_SN, TMNL_ID, FCLT_TYPE_CD)
```

신규 결과 테이블은 `(SMLT_ID, SMLT_MDL_SN)`을 FK로
`TN_PM_SMLT_STNG(SMLT_ID, SMLT_MDL_SN)`에 직접 연결한다.
별도 계산 상태 테이블·시퀀스·대체 ID는 만들지 않는다.

`TN_PM_SMLT_RSLT_DTL`과는 원천 여러 행에서 파생 결과 여러 행을 만드는 관계다.
상세 PK에는 실행일시·실적일시·제출시설코드까지 있으므로 `SMLT_ID` 단독 FK로 연결하지 않는다.
같은 실행·모델에 서로 다른 실행일시의 원천이 있으면 임의 합산하지 않고 산출을 실패시킨다.

한 원천 결과 시각의 값이 체크인의 여러 1분 계산·10분 집계에 사용될 수 있다.
따라서 파생 구간 시각과 원천 `SMLT_ACTL_DT`를 단순 동등 조인하지 않는다.

## 4. 10분 구간 규칙

- 모든 구간은 `[SEC_BGNG_DT, SEC_END_DT)`이고 길이는 정확히 10분이다.
- 시작은 매시 00·10·20·30·40·50분, 초는 0이다. DB 제약으로 검증한다.
- 날짜를 포함한 `TIMESTAMP(0)`이며 업무 시각은 Asia/Seoul이다.
- 대상일 23:50 구간의 종료는 다음 날 00:00이다. 24:00 문자열을 저장하지 않는다.
- 대상일 이전 구간도 같은 키 체계로 저장한다. 당일 144행으로 제한하지 않는다.
- 체크인은 기존 원천 시각을 구간 시작으로, 출국장은 구간 끝으로 해석한다.
  저장 어댑터가 양쪽을 위 공통 구간으로 변환한다. 원천 시각 의미 자체는 CAST 계약 확인 대상이다.

체크인은 `ChknQueueCalculator`의 1분 계산 후 10분을 묶는다.
`queue[m]`은 해당 분 처리 후 큐이므로 `[b,e)`의 시작 큐는 `queue[b-1]`, 종료 큐는 `queue[e-1]`이다.
시작 시점의 큐를 확인할 이력이 없으면 시작 큐는 NULL이다.

출국장은 원천 시각 `e`의 처리인원·대기시간 합을 `[e-10분,e)`에 연결한다.
종료 큐는 시각 `e`, 시작 큐는 시각 `e-10분`의 합산 큐다.
두 경계가 유효할 때 `max(0, 종료큐-시작큐+처리인원)`을 도착여객수로 저장한다.
경계 이력이 없으면 도착여객수도 NULL이다.

정수 집계도 향후 소수 원천을 수용할 시간 합계 컬럼에 그대로 저장할 수 있다.
현재 원천과 체크인 분 단위 계산에서 나오는 정수 초 합계는 위 정밀도에서 손실 없이 보존한다.
새 원천의 소수 자릿수가 6을 넘으면 묵시적 반올림에 의존하지 말고 자료형·동등성 검증을 다시 한다.

현재 화면 의미를 보존하기 위해 큐 평균의 표본도 구분한다.
CHKN은 1분 종료 큐 10개의 합계·건수·최대값, DEP는 원천 10분 종료 큐 1개의 합계·건수·최대값이다.
DEP 최대값은 구간 안의 실제 최대 대기인원을 의미하지 않는다.
시설 행이 없는 시각의 0 표본 포함 여부는 현재 화면별 경로와 대조해야 하며 임의로 확장하지 않는다.

주요 재집계:

```text
30분 평균 대기시간(초) = SUM(WTNG_PSEC_SUM) / SUM(WTNG_VLD_PSG_CNT)
큐 평균 = SUM(WTNG_PSG_CNT_SUM) / SUM(WTNG_NOCS)
큐 최대 = MAX(MAX_WTNG_PSG_CNT)
처리인원 = SUM(PRCS_PSG_CNT)
평가시각 t의 큐 = 종료시각이 t인 구간의 END_WTNG_PSG_CNT
CHKN 부스당 분당 처리율 = SUM(PRCS_CPCT) / SUM(PRCS_VLD_OPER_CNTOM_SUM)
```

마지막 산식은 기존 `ChknQueueSeries.serviceRateOf()`의 조건부 운영 대수 합계를 보존한다.
단순 운영 대수 평균 또는 `PRCS_PSEC_SUM / PRCS_VLD_PSG_CNT`로 대체하면 기존 μ와 달라질 수 있다.
DEP 처리시간 합계는 현재 Mapper의 시설유형·출국장·시각별 MAX 처리시간 후 가중합 의미를 유지한다.
레인별 정확한 가중합으로 바꾸는 개선은 별도 변경이다.

## 6. 관측·누락과 경계

- 평균 대기시간 판정은 평가시각 직전 30분이다. 10분 경계 t에서는 연속된 세 구간을 읽는다.
- 세 구간 모두 `OBSRVN_YN='Y'`, 유효 대기시간 인원 합계가 전체 처리인원 합계와 일치하고
  처리인원이 양수일 때만 등급용 평균을 계산한다. 유효 인원만 골라 정상 평균으로 표시하지 않는다.
- CHKN의 관측 여부는 현재 터미널 결과 시각·분별 관측 배열을 따른다. 마지막 결과 이후 꼬리 구간은
  계산값이 있어도 미관측이다. 관측 N이 계산 실패를 뜻하지는 않는다.
- DEP는 구간의 시작·끝 원천 시각이 모두 터미널에 있어야 10분 관측으로 기록한다.
  연속 세 구간의 관측은 기존 30분 창의 네 결과 시각 존재 검사에 대응한다.
- 터미널 결과 자체가 없는 경우와 특정 시설 행만 없는 경우를 구별한다.
  후자의 0 처리 여부는 현행 시설 어댑터를 대조하여 정한다. 원천 누락을 일괄 0으로 채우지 않는다.
- 미관측이어도 현재 알고리즘이 계산한 부분 합계는 보존할 수 있다. `OBSRVN_YN`을 무시한 판정은 금지한다.
- 처리인원 0은 정상 0일 수 있으나 평균 대기시간은 산정 불가다.
  대기시간 NULL 여객은 `PRCS_PSG_CNT - WTNG_VLD_PSG_CNT`로 보존한다.
- 수량 NULL은 미확인, 0은 확인된 미운영이다. 미확인 수량을 0으로 저장하지 않는다.

## 7. 상태 테이블 없는 최초 저장과 조회 보완

새 시뮬레이션 실행은 일일·사용자 모두 새 `SMLT_ID`를 가진다.
기존 결과를 바탕으로 같은 ID의 파생 큐만 다시 생성하는 별도 복구 기능은 이번 범위에 포함하지 않는다.
새 결과 수신 후 최초 저장 단위는 `(SMLT_ID, SMLT_MDL_SN, TMNL_ID, FCLT_TYPE_CD)`다.
저장 전 해당 범위의 전체 10분 결과와 기대 시설·구간 목록을 메모리에서 대조한다.
그 후 해당 범위의 전체 결과를 한 트랜잭션으로 삽입한다.
계산 실패나 삽입 실패 시 파생 쓰기를 롤백하고 원천 수신 성공은 보존한다.
분할 커밋으로 일부 시설·시간대만 노출하지 않는다.

기존 수신 경로의 실행·모델 중복 처리 정책을 유지하고, 파생 결과도 PK로 중복 삽입을 거부한다.
기존 파생 행을 삭제하거나 덮어쓰는 경로는 추가하지 않는다.
계산 상태 테이블·재생성용 잠금·작업 큐·입력 스냅샷은 추가하지 않는다.

관측 N 행도 유효한 저장 결과일 수 있다. 결과 생성 여부와 관측 여부는 별개다.
행 1건 존재만으로 전체 생성 완료를 판정하지 않고, 조회에 필요한 시설·구간의 완전성을 검사한다.
비어 있는 정상 범위와 미생성을 구분할 근거가 없으면 정상 0명으로 표시하지 않는다.
기대 목록은 실행 리소스와 기존 원천 범위에서 얻고, 당일 144행 고정으로 판단하지 않는다.

최초 생성이 없거나 조회 범위 결과가 불완전하면 해당 응답의 시설유형·터미널 범위를 기존 Java 계산으로 보완한다.
같은 범위 안에서 저장된 일부 행과 재계산한 일부 행을 섞어 중복 집계하지 않는다.
Java 보완 결과도 같은 10분 통계 구조로 집계하고 공통 근사 평가기에 전달한다.
보완 경로만 기존 분별 FIFO 예측을 사용하여 저장 유무에 따라 계산 방식이 달라지게 하지 않는다.
계산이 반환한 미관측·산정 불가를 실패로 간주하여 재시도하지는 않는다.
상태 테이블이 없으므로 미생성·생성 중·실패 이유를 결과 행만으로 구별할 수는 없다.
실패 원인은 기존 수신 처리 기록·애플리케이션 로그로 확인한다.
Java 보완은 조회 응답을 만들기 위한 계산이며, 결과 테이블에 자동 저장하거나 기존 행을 갱신하지 않는다.

## 8. 10분 저장으로 보존되는 것과 근사 평가

10분 경계의 큐, 10·30·60분 처리인원·가중 평균, 큐 표본 평균·최대, CHKN 처리율은 위 통계로 보존할 수 있다.
원천 CAST 상세는 계속 보존한다. CHKN 차트의 SBD 추가 집계도 별도 경로로 유지한다.
등급 문자열·추천 수량·해소 예측은 저장하지 않는다.
혼잡등급은 조회 시점 `TN_PM_PSG_PRCS_GRD`로 판정하고 추천·해소도 같은 최신 기준표로 계산한다.
기준표 변경만으로 저장된 10분 기본 통계를 바꾸지 않는다. 판정·예측은 조회 때 다시 계산된다.

다음은 10분 통계만으로 기존 결과를 정확히 복원할 수 없다.

- 구간 내부의 분별 큐·유입·처리인원과 처리된 여객의 분별 대기시간 합
- 잔여 대기자의 도착 시각 분포와 자정 시작 FIFO 상태
- CHKN 일일 대기시간 95분위에 필요한 일일 대기시간별 처리인원 분포
- 10분 경계가 아닌 평가시각의 정확한 이동평균

현재 `QueueWaitWindow` 예측은 미래 1분마다 관측 창에서 과거 분별 처리 이력을 빼고,
남아 있는 FIFO 도착군을 이어 쓴다. 사용자 결정에 따라 이번 공통 평가 경로는 아래 10분 근사를 적용한다.
기존 분별 FIFO 예측·추천·해소값과 달라질 수 있으며, 그 차이를 허용한다.

### 8.1 관측 통계와 분별 처리 이력

평가시각은 10분 경계 t다. `[t-30분,t)`의 연속 세 구간을 읽는다.
관측·유효성은 §6을 먼저 검사하고, 불완전한 이력을 정상 값으로 채우지 않는다.
평균 대기시간 판정은 저장한 원래 합계·분모로 계산한다. 근사를 이유로 등급용 평균을 바꾸지 않는다.

예측기에 필요한 30개 분별 이력은 각 10분 구간에서 다음과 같이 만든다.

```text
분별 처리인원 = PRCS_PSG_CNT / 10.0
분별 대기시간 합계(초) = WTNG_PSEC_SUM / 10.0
```

분배 과정의 소수 인원·시간 합계를 정수로 반올림하지 않는다.
관측 창 전체의 합계·분모는 보존하지만 창이 미래 1분씩 이동할 때의 과거 이력 제외량은 근사다.
평가기 입력 배열은 가장 오래된 분부터 `[t-30분, ..., t-1분]` 시간순으로 구성한다.

### 8.2 잔여 대기자의 도착군 근사

평가시각 t의 잔여 대기인원 Q0는 종료시각이 t인 행의 `END_WTNG_PSG_CNT`다.
Q0가 확인된 0이면 빈 도착군을 사용한다. Q0가 NULL이면 산정 불가다.

가장 최근 구간부터 과거 방향으로 연속 행을 읽는다.
각 구간의 `ARR_PSG_CNT / 10.0`을 그 안의 분별 도착인원으로 균등 분배하고,
가장 최근 분부터 Q0만큼 도착군을 채운다. 처리되지 않은 여객을 최근 도착 순서에서 찾는 FIFO 근사다.
도착군에는 평가시각 기준 경과 분을 유지하며, 모두 대기 0분으로 초기화하지 않는다.
역추적 수집 후 평가기에 전달하는 순서는 오래 기다린 순(`ageMin` 내림차순)이다.
최근 순서 그대로 전달하여 FIFO가 뒤집히지 않도록 앞에 삽입하거나 전달 전에 순서를 정렬한다.

CHKN의 `ARR_PSG_CNT`는 기존 1분 FIFO 계산의 도착인원을 10분 합산한 값이다.
DEP는 기존처럼 경계 큐와 처리인원의 보존식으로 얻는다(§4).
DEP는 기존 최대 180분 역추정 범위를 유지하고, CHKN은 저장된 실제 계산 시작점까지 이력을 사용한다.
임의로 CHKN까지 180분으로 자르거나 이전 일자 이력을 버리지 않는다.

연속 행이 끊기거나 도착인원·경계 큐가 미확인이거나 필요한 이력이 미관측이면 복원을 중단한다.
Q0를 채우지 못한 경우 잔여 도착군 산정 불가 사유를 유지한다.
직전 30분 관측이 충분하면 등급용 평균은 계산할 수 있어도 추천·해소는 산정 불가일 수 있다.
이 상태는 저장 결과 미생성과 다르므로 원천 계산 재시도의 조건으로 사용하지 않는다.

### 8.3 공통 평가와 화면 범위

λ·μ·운영 수량·Q0는 기존 관측 구간·처리율 정의를 따른다.
CHKN μ는 §5의 처리용량·유효 운영 대수 합계로 구하고, DEP μ는 기존 처리시간 집계 의미를 유지한다.
위 분별 처리 이력과 잔여 도착군을 `QueueWaitWindow` 형태로 만들어 기존 공용 평가기에 전달한다.
정상상태 이론값과 유체 FIFO 예측의 의미를 바꾸거나 추천량을 보유 수량으로 자르지 않는다.

카드·맵·체크인 상세·혼잡해소 팝업은 같은 공통 조회·평가 경로를 사용한다.
동일 실행·시설·평가시각에서 등급·등급용 평균 대기시간(`cgnWtngSec`)·추천(`reqCnt`)·해소(`cgnClearMin`) 결과를 일치시킨다.
맵·상세의 별도 슬롯 지표는 기존 `[hhmm,hhmm+30분)` 정의를 유지한다.
카드·등급·추천의 직전 30분 관측 창과 혼동하여 슬롯 지표의 구간을 바꾸지 않는다.
팝업에서 사용자가 바꾼 운영 수량·목표 시간은 같은 입력 통계에 적용하여 요청 시 계산한다.

대시보드 차트·PRIME TIME과 CHKN 일일 95분위 계산은 기존 경로를 유지한다.
기존 차트가 호출하는 1분 FIFO 자료 생성까지 전역으로 10분 근사 구현으로 교체하지 않는다.
10분 근사는 공통 카드·상세·시나리오 평가 입력 어댑터에 적용한다.

관측 이전 이력은 CHKN의 실제 계산 시작점과 DEP 최대 180분 역추정 범위를 충분히 포함해야 한다.
180분만 저장하면 모든 CHKN 잔여 큐가 복원된다고 가정하지 않는다.
저장 시작 경계가 10분에 맞지 않으면 첫 10분 행은 부분 관측으로 기록하고 값이 없는 앞부분을 만들지 않는다.

## 9. 구현 전 필수 입력 점검

1. CHKN 배정 부스 입력을 현행 운영표 직접 조회에서 실행의 STNG CA 리소스 기준으로 정리한다.
   WhatIf 사용자 조건과 일일 조건을 같은 입력 해석으로 검증한다.
2. 신규 결과의 큐 계산은 해당 실행의 STNG 리소스 참조를 사용한다.
   일일 `001` 리소스가 CAST 사용 시점과 결과 수신 시점 사이에 변경될 수 있는지는 실제 연계 환경에서 점검한다.
   기존 파생 결과를 최신 운영표에 맞춰 자동 갱신하거나 동일 ID를 다시 산출하는 기능은 만들지 않는다.
3. `retrieveChknQueueRawList`·`retrieveRsltByUnitList`에 모델별 분리가 없다.
   PK에 모델번호만 추가하지 말고 조회·집계 이전부터 필터를 적용한다.
4. 시설 목록·누락 처리·일시 정규화·처리시간 fallback·미관측 꼬리 구간을 기존 경로와 대조한다.
5. 시설유형별 결과 공개 단위는 터미널 전체다. 같은 유형의 카드·맵·상세가 같은 커밋 결과를 읽게 한다.
6. 도입 전 실행 ID는 저장 결과가 없으면 조회 응답에서만 Java 계산으로 보완한다. 과거 ID 일괄 채우기는 구현하지 않는다.
   기존 요청 삭제가 STNG·원천을 보존하는 정책도 유지한다. 실제 원천/설정 정리 경로가 있으면 종속 파생 행을 먼저 정리한다.
   신규 정리 배치나 자동 연쇄 삭제는 만들지 않는다.

## 10. 검증과 적용 범위

이번 작업은 표준단어와 기존 참조 코드의 정적 대조, DDL 구조·키·제약 점검까지다.
신규 결과 테이블의 27개 컬럼에 사용한 모든 구성 약어가 표준단어에 있음을 검사했다.
표준단어 인용 줄번호, 컬럼별 COMMENT·설계 설명, PK 구성, STNG 직접 참조,
9개 제약 이름의 중복·30바이트 제한, 10분 경계 제약, 공백 오류도 정적으로 확인했다.
프런트·백엔드 동작 변경이 없어 프런트 빌드·lint 대상은 없다.
Java 컴파일·Oracle DDL 실행·연계 검증은 수행하지 않았다.

실제 구현 시 필요한 검증:

- Oracle 버전·실제 STNG 키 자료형·부모 PK를 확인하고 별도 검증 DB에서 DDL을 실행한다.
- 중복 자연키, 잘못된 10분 경계, 음수·유효인원 초과, 부모 누락 행을 거부하는지 확인한다.
- 동일 원천에 대해 큐·처리인원·평균 대기시간·처리율의 10분→30분 재집계 값을 대조한다.
  추천·해소는 기존 값과의 동등성 대신 공통 평가 경로 간 일치와 근사 입력의 합계 보존을 검증한다.
  중간 반올림은 하지 않는다.
- 일일/WhatIf, T1/T2, 모델 분리, 운영 수량 변경, 자정·누락·0명·미운영·꼬리 구간을 확인한다.
- DEP 대기시간 NULL, 시설 행 누락, 터미널 전체 결과 누락을 각각 검증한다.
- 파생 실패에도 원천이 보존되고 일부 시설·구간만 커밋되지 않는지 확인한다.
- 새 실행은 새 ID에 저장되고, 중복 결과로 기존 파생 행을 덮어쓰지 않는지 확인한다.
- DB 조회와 Java 보완 경로가 같은 10분 통계에 대해 같은 추천·해소 결과를 내는지 확인한다.
- 카드·맵·체크인 상세·팝업의 동일 조건 결과가 일치하고 차트·PRIME TIME·95분위 경로는 유지되는지 확인한다.
- 잔여 도착군 복원 부족과 30분 관측 부족을 구분하고, 근사 분별 인원의 소수를 보존하는지 확인한다.
- 시설·모델당 하루 기본 144행에 사전 이력이 더해지는 저장량과 실제 전체 산출 시간을 측정한다.

적용 순서는 초안 검토 → 실제 스키마 대조 → 검증 DB DDL → 최초 저장·조회 보완 구현 → 병행 대조 → 조회 전환이다.
현재 API DTO·enum·CSS·화면과 기존 수신 트랜잭션은 변경하지 않는다.

## 11. 대시보드 전환 범위 인터뷰

1차 인터뷰에서 확정한 내용:

1. 기본 통계만 저장하고 추천·해소는 조회 시 계산한다.
2. 최신 기준표 적용을 유지한다. 큐 통계는 그대로 읽고 조회 시 판정·예측을 다시 계산한다.
3. 결과가 없거나 불완전하면 기존 Java 계산으로 보완한다.

2차 인터뷰에서 확정한 내용:

1. CHKN 추천·해소는 10분 통계로 근사하고 기존 값과 차이를 허용한다.
2. 이번에는 카드·대표 혼잡등급을 저장 결과 조회로 전환하고 차트·PRIME TIME은 기존 경로를 유지한다.

3차 인터뷰에서 확정한 내용:

1. 카드·맵·체크인 상세·혼잡해소 팝업의 공통 평가 경로에 같은 10분 근사를 적용하여 화면 간 값 일치를 유지한다.

실행 ID와 저장 흐름 정리:

- 일일·사용자 모두 새 실행은 새 `SMLT_ID`다.
- 같은 ID로 파생 큐만 다시 만드는 운영 복구 절차는 별도로 요구되지 않아 이번 범위에서 제외한다.
- 신규 결과 수신 후 최초 저장하며, 미생성·불완전 결과는 조회 응답에서만 기존 Java 계산으로 보완한다.

화면·평가·저장 범위 결정은 완료했다.
실제 운영 입력·Oracle 스키마 대조는 §9·§10의 구현 전 점검으로 남는다.

대시보드 소스에서 확인한 차이:

- CHKN 시간차트는 매분 CC+SBD 합산 큐의 피크를 구한다.
  `max(CC) + max(SBD)`로는 같은 값을 얻을 수 없어 합성 후 피크를 보존해야 한다.
- DEP 시간차트는 LGT+LC+SC+SR 대상이며, 시설 카드는 SC+SR 대상이다.
- PRIME TIME은 LS·CC·CK·SBD·LGT·LC·SC·SR을 포함한다.
- 일반 화면의 시각 눈금은 10분이지만 API의 임의 HHmm 요청은 현재 막지 않는다.
  전환 대상 API는 10분 경계를 검증하고 경계를 벗어난 요청은 조건 오류로 처리한다.
  원천 `avlTimes`의 선택 후보도 같은 경계에 맞춰 화면·API의 허용 시각을 일치시킨다.

기본 통계를 DB에서 조회하는 경우에도 API는 DTO 조립·날짜/숫자 변환을 담당한다.
SQL 합계·가중 평균 같은 단순 집계와 FIFO 재계산·시나리오 예측은 구분한다.
날씨·운항 등 다른 원천에서 읽는 대시보드 정보까지 공통 큐 테이블에 넣는 것은 이번 범위가 아니다.

### 12.2 실제 트랜잭션 연결 계약

현재 `CastApiServiceImpl`은 클래스 전체에 `@Transactional`이 있고 `insertResult`는 private 메서드다.
컨트롤러 → 프록시 `saveResult(param, context)` → `insertResult` → STNG/상세 저장 → 사용자 완료 순서이며,
서비스 프록시를 빠져나갈 때 원천 트랜잭션이 커밋된다.

따라서 `insertResult` 끝에서 바로 `REQUIRES_NEW` 서비스를 호출하면 새 트랜잭션이 미커밋 STNG를 보지 못할 수 있다.
기본 연결 방식은 원천 트랜잭션에 등록한 커밋 후 콜백에서 별도 Spring bean의 public 저장 메서드를 호출하는 것이다.
콜백에는 실행·모델 등 필요한 식별값만 전달하고 응답 XML을 다시 파싱하지 않는다.
별도 저장 bean은 `REQUIRES_NEW`로 실제 새 트랜잭션을 시작한다.
private 메서드나 같은 클래스 자기 호출에 애너테이션만 붙여 분리했다고 간주하지 않는다.

콜백은 원천 커밋 성공 때만 실행한다. 모델 정보 수신·WhatIf 상태 수신 분기는 생성 대상이 아니다.
원천 커밋 실패 시 파생 행은 저장하지 않는다. 별도 비동기 큐·예약 재시도 없이 커밋 후 최초 생성만 연결한다.
예상 가능한 계산·DB 실패는 원인 로그를 남기고 CAST의 원천 저장 성공 응답을 실패로 뒤집지 않는다.
발생 가능한 예외만 구체적으로 처리하고 `Exception`·`RuntimeException` 포괄 catch를 새로 넣지 않는다.
예상하지 못한 프로그래밍 오류까지 정상 성공으로 숨기지 않는다.

커밋 후 콜백의 DB 쓰기에도 새 트랜잭션이 필요하다는 근거는
[Spring TransactionSynchronization.afterCommit](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/transaction/support/TransactionSynchronization.html#afterCommit())을 따른다.
실제 백엔드의 Spring 버전에서 지원하는 콜백 API를 확인한다. 이 참조 사본에는 의존성 빌드 파일이 없다.

### 12.3 실행 입력과 모델 선택

저장 단계는 수신에서 확정한 `(SMLT_ID, SMLT_MDL_SN)`을 그대로 사용한다.
조회 API에 새 모델 필드를 추가하지 않고, 해당 실행의 모델이 유일하면 그 모델을 사용한다.
여러 모델 중 하나를 확정할 수 없으면 명시적 오류로 처리한다. 첫 행 선택·모델 합산으로 임의 처리하지 않는다.
원천 SQL도 같은 모델로 필터한다. 기존 차트 호출 계약을 바꾸지 않도록 신규 조회/명시적 모델 인자를 분리한다.

CHKN의 기존 `retrieveChknMapGroupByIsland(excnYmd, tmnlId)`는 운영표 직접 조회라 그대로 신규 입력에 쓰면 안 된다.
STNG의 `CKNCT_ALCTN_RSRC_ID`를 받아 부스별 운영 구간 행을 읽는 내부 조회를 추가한다.
분기와 원천의 근거는 다음 두 SQL에 있다.

- `java/mapper/CastApiMapper.xml#retrieveCounterAllocation`: CA001/사용자 CA의 리소스 발행 규칙.
- `java/mapper/CastDsbdMapper.xml#retrieveChknAlnAssignmentList`: 일일 운영자료/사용자 ATRB 참조 분기.

두 쿼리는 각각 발행용 LISTAGG DTO·한 평가시각 항공사 집계이므로 반환값을 그대로 계산 입력으로 쓰지는 않는다.
같은 원천 분기를 재사용해 하루치 부스 코드·운영 시작/종료 행을 조회한다. CSV/XML로 변환했다 다시 파싱하지 않는다.
일일 기준일자는 STNG의 `EXCN_YMD`를 바인딩하고 `SYSDATE`로 대체하지 않는다.
새로운 입력 보존 테이블은 만들지 않는다.

### 12.4 행 생성·완전성·조회 보완 계약

저장 때 기대 시설은 기존 CHKN/DEP 어댑터의 대상 목록을 유지한다.
실행 운영 리소스와 해당 실행·모델 원천의 시설 목록을 사용하되, 시설 마스터 전체를 정상 0명으로 확장하지 않는다.
기존에 알려진 미운영 시설과 원천 결과가 없는 미확인 시설을 구별한다.

각 대상 시설은 필요한 사전 이력부터 대상일 종료까지 연속 10분 행을 만든다.
CHKN은 실제 계산 시작점, DEP는 최소 자정 이전 180분을 포함한다. 첫 부분 구간은 §4·§6대로 표시한다.
미관측·꼬리 구간도 명시적 행으로 저장하고 `OBSRVN_YN='N'`을 사용한다.
큐 미확인은 NULL, 확인된 미운영은 0, 실제 큐 표본 부재는 `WTNG_NOCS=0`과 최대값 NULL로 구별한다.
DEP의 특정 시설 행 부재는 기존 어댑터의 0 큐 해석과 표본 제외 규칙을 각각 보존한다.

조회 시 필요한 시설·세 관측 구간과 도착군 역추적 범위가 존재하는지 확인한다.
필요한 물리 행이 없거나 중복·잘못된 경계가 있으면 해당 시설유형·터미널 응답 범위 전체를 Java 보완으로 선택한다.
실제 원천·계산 시작 경계에 도달한 것은 정상적인 이력 종료이며, 그 이전 자료가 원래 없는 것은 행 누락이 아니다.
경계는 실행·모델·시설유형·터미널별 원천 최소 시각과 계산 범위의 가벼운 조회로 확인한다.
기대 저장 범위 안의 물리 행 누락만 보완 조건으로 사용하고, 원래 짧은 이력은 관측/도착군 산정 불가로 처리한다.
반면 관측 N, 처리인원 0, 대기시간 NULL 여객, 도착군 복원 부족은 저장된 자료의 유효성 상태다.
이 경우에는 정상 저장 결과를 유지하고 지표별 산정 불가를 반환한다. 계산 실패로 오인하여 반복 보완하지 않는다.
기대 시설이 없다는 근거가 실행 리소스·원천 양쪽에서 확인되면 빈 결과를 정상 반환할 수 있다.

완전성 검사를 위해 기존 FIFO 계산기를 먼저 호출하지 않는다.
시설 목록·필요한 원천 경계의 가벼운 조회와 저장 행의 키·관측 메타데이터로 검사한다.
DB가 준비된 일반 조회에서 부스별 원천 전체 읽기·1분 FIFO 재계산을 다시 수행하면 구현 목표를 달성한 것이 아니다.
차트·KPI가 별도 기존 경로에서 수행하는 계산은 이 제한의 대상이 아니다.

DB 통신 실패·잘못 적용된 스키마·모호한 모델 선택을 저장 행 미생성과 동일시하지 않는다.
그러한 오류는 기존 조회 실패 경로로 전달한다. 보완 분기에 포괄 catch를 두어 장애를 감추지 않는다.
Java 보완도 실패하면 기존 API 오류 정책을 따른다. 보완 결과는 응답에만 사용하고 DB에 저장하지 않는다.

### 12.5 구현 순서와 완료 기준

1. DDL·신규 Mapper·행 DTO와 순수 10분 집계/근사 어댑터를 작성한다.
2. STNG CA 기반 부스 운영 구간과 모델별 원천 조회를 연결한다.
3. 최초 산출을 원천 커밋 후 별도 트랜잭션에 연결한다.
4. 저장/보완 선택을 제공하는 공통 조회 서비스를 만든다.
5. 대표 등급·카드·맵·체크인 상세·팝업의 평가 경로를 연결한다. 차트·PRIME TIME·KPI를 보호한다.
6. 아래 자료와 §10으로 단위 비교·통합 검증을 수행하고, 실행하지 못한 실제 백엔드·DB 검증을 보고한다.

구현 확인용 최소 예:

- 연속 세 행의 처리인원 `[10,20,30]`, 대기시간 합계 초 `[600,2400,5400]`, 유효인원이 처리인원과 같으면
  직전 30분 평균은 `8400/60=140초`다. 세 평균을 단순 평균하지 않는다.
- 위 자료를 각 10분 안에서 균등 분배해도 30분 처리인원·시간 합계는 그대로여야 한다.
- Q0=5, 최근 구간 도착인원=10이면 1분당 도착 1명으로 최근 5개 분의 도착군을 취하고,
  평가기에 경과 분 `[5,4,3,2,1]` 순서로 전달한다. 총인원은 5다.
- 같은 세 행 중 한 행이 물리적으로 없으면 범위 전체 Java 보완, 행이 존재하고 관측 N이면 등급 산정 불가다.
- Java 보완과 DB 조회가 같은 10분 통계를 만들었을 때 등급·추천·해소는 같아야 한다.
- 동일 ID·모델의 중복 수신은 기존 정책대로 거부하고, 새로운 실행은 새 ID에만 최초 저장한다.

구현 완료 보고에는 수정한 Java 참조 파일·DDL, 검사 결과, 실제 환경에서 미검증인 항목을 구분한다.
이 저장소에서는 Java 컴파일 완료를 주장하지 않는다. 프런트 수정이 있으면 `npx tsc -b`·`npx eslint .`을 실행한다.
실제 DB가 연결되지 않았다는 이유만으로 참조 소스 구현을 중단하지 않는다.
DDL 적용·CAST 연계 성공은 별도 실제 환경 검증이 끝난 후에만 완료로 표시한다.

### 14.2 구현 중 정한 해석

1. **배정 부스 입력**: STNG `CKNCT_ALCTN_RSRC_ID`를 분 단위로 읽는다. CA001은 발행 SQL과 같이
   `NVL(EST, LAST)` 시각, 시작 > 종료이면 익일 종료하며 그 외에는 발행 SQL의 `LAST_RON_YN` · `EST_RON_YN` 선택 규칙,
   `TN_CA_ALN_PGE` 존재, A/B 유형, X/Y/R/S 제외를 따른다.
   사용자 CA는 `CHKN_OPEN/CLOSE_PRNMNT_DT`를 그대로 읽는다. 기준일자는 `EXCN_YMD`다.
   차트 · KPI의 1분 경로도 같은 입력을 쓴다 — 카드와 차트의 큐가 갈리지 않게 하기 위해서다.
   기존 운영표 시 단위(시작 내림 · 종료 올림)에서 분 단위로 바뀌어 기존 화면 값과 달라질 수 있다.
2. **모델**: 저장은 수신에서 확정한 모델, 조회는 `CastSmltService.retrieveUniqueSmltStng`(모델이 여럿이면 오류).
   차트 · KPI 경로는 기존 계약대로 모델을 거르지 않는다.
3. **저장 범위**: CHKN `[계산 시작 10분 내림, 24:00)`, DEP `[min(자정-180분, max(전날 0시, 첫 결과-10분)), 24:00)`.
   CHKN 첫 부분 구간은 시작 큐 · 도착 · 시작 운영대수가 NULL이다. 계산 시작과 같은 경계의 행은 시작 큐만 NULL이다.
4. **잔여 도착군**: §8.2대로 행이 없거나(저장 범위 시작), 관측 N이거나, 도착인원 · 경계 큐가 NULL이면 멈춘다.
   CHKN의 결과 간격 · 꼬리 구간에 1분 계산의 도착값이 있더라도 미관측 이력을 도착군 복원에 사용하지 않는다.
5. **DEP 종료 큐**: 터미널 결과가 없는 시각은 NULL(미확인)로 둔다. 기존 어댑터는 0이었다.
6. **완전성 검사**: 저장 단위의 하루치 행, 원천 시설 단위별 첫 결과 시각(`retrieveFcltWtngSrcList`), DEP 운영표만 읽는다.
   기대 시설은 CHKN 고정 13개 아일랜드, DEP는 원천 ∪ 운영표 출국장이다. 하나라도 어긋나면 그 응답의 시설유형 ·
   터미널 전체를 Java로 계산하고 저장하지 않는다. 보완 결과가 기대 범위와 다르면 오류로 올린다.
7. **실패 기록**: 최초 저장 실패는 애플리케이션 로그와 수신 로그 `errorMsg`(`CastApiContext.addFailure`)에 남고
   CAST 응답은 성공 그대로다. `afterCommit`이 `CastApiExecutor`의 `action.apply` 안에서 끝나므로 실행기는 바꾸지 않았다.
8. **시각 경계**: 대표 등급(`retrieveDailySmltTmnlSmry`)은 오류 응답, 카드는 `IllegalArgumentException`, 팝업은 실패 응답으로
   10분 경계가 아닌 `hhmm`을 거절한다. `avlTimes`는 서버와 화면(`defaultTime`) 양쪽에서 10분 경계로 내린다.

### 14.3 검증

- `cast/` · `castapi/` · `cmmn/` · `utils/`를 JDK 17 + Spring 5.3.30/5.3.32 + MyBatis 3.5.13 + lombok 1.18.30으로 컴파일했다.
  사내 프레임워크(`aoms.framework`, egovframe)는 최소 스텁으로 대체하고, 변경과 무관한 외부 의존 파일
  (`HwpxUtils`, `DataSetUtils`, `CastOperHrServiceImpl`, `CastApiController`, `AtchFileUtils`)은 제외했다. 실제 백엔드 빌드는 아니다.
- 저장소 밖 하네스로 29개 검사 통과: §12.5 예 전부, CHKN 1분 경로 대비 30분 슬롯 지표 · 평균 대기시간 · 등급 · 평가 입력 일치,
  DEP 기존 `DepQueueWindow` 대비 평가 입력 · 평균 · 잔여 도착군 · 추천 · 해소 일치, 저장 행 왕복과 Java 보완 결과 일치,
  생성 행의 DDL CHECK 제약 충족. CHKN 추천 · 해소는 1분 예측과 일부 평가시각에서 달랐다(허용 차이).
- 프런트: `npx tsc -b`, `npx eslint .` 통과.

미검증: Oracle DDL · `INSERT ALL` 실행, 실제 Spring 버전의 `TransactionSynchronization` 기본 메서드 지원,
CAST 연계 수신 흐름, 실데이터 저장량 · 산출 시간, 원천 시각 의미(§4).

### 14.4 검토 후 보완

수정 전 구현 46개 파일은 `d3311d0`으로 main에 커밋 · 푸시했다.

- 관측 평균은 10분 행의 원래 처리인원 합계 · 대기시간 합계로 계산한다. 분별 균등 분배 이력은 미래 예측에만 사용하고,
  카드 · 팝업 · 예측 시작시각도 같은 관측 합계를 사용한다. 정확히 1200초 · 2400초 · 3600초인 평균의 등급 경계를 보존한다.
- 도착군 복원은 §8.2대로 미관측 행 또는 도착인원 · 경계 큐 미확인에서 중단한다.
  직전 30분이 관측됐으면 평균 · 등급은 유지하며, 잔여 대기자의 도착을 확인할 수 없으면 추천 · 해소만 산정 불가다.
- CA001 종료일은 CAST 발행 SQL의 RON 결정식을 따른다. 시작시각이 종료시각보다 늦으면 익일이고,
  그 외에는 LAST/EST 시각 존재 여부에 따른 익일 플래그를 적용한다.

회귀 검사와 실행 방법은 `java/verify/README.md`에 있다. 변경 도메인을 기존 검증용 참조 클래스와 함께 컴파일해
Java 78개 검사를 통과했고, 실제 Mapper CASE 식과 CAST 발행 SQL을 대조한 로컬 검사 28개를 통과했다.
기존 외부 하네스는 §12.5 도착군 예제의 NULL 경계 큐를 알려진 값으로 보정한 임시 사본에서 29개 검사를 통과했다.
이 예제는 큐 보존식도 만족하도록 보정했고, 외부 원본은 보존했다. 실제 백엔드 빌드 · Oracle · CAST 연계 미검증 범위는 그대로다.
