# 대시보드 조회 구간 요약정보

요약정보는 선택한 조회 시각부터 60분을 사용한다.
왼쪽 운항편·여객수는 조회 시각, 1시간 후, 2시간 후부터 각각 60분을 3행으로 표시한다.
09:00 조회는 09:00~10:00, 09:10 조회는 09:10~10:10이다.
23시대의 종료는 기존 운항 집계와 같이 해당 일자 24시로 제한한다.
시간 변경 후 조회하거나 Prime Time을 선택하면 같은 구간 조건으로 다시 계산한다.
위쪽 피크시간 정보는 기존 터미널별 하루 대기인원 피크를 유지한다.

운항편·여객수 박스의 좌측 상단에는 `전일 대비`를 테두리에 겹쳐 표시하고,
각 수치 오른쪽 괄호에 전일 같은 구간 대비 증감을 표시한다.
`현재`는 조회를 확정한 시각이며 PC 시계가 진행해도 자동으로 바뀌지 않는다.

`TmnlSmryDto.intrvlList`는 아래 항목을 조회 시각, +60분, +120분 순서로 반환한다.
요청 조건과 기존 `intrvl*` 필드는 유지하며, 기존 네 운항 집계 필드는 첫 항목과 같다.

| 항목 필드 | 내용 |
|---|---|
| `bgnHhmm`, `endHhmm` | 집계 시작(포함)·종료(미포함), `HHmm`. 당일 마지막 종료는 `2400` |
| `fltCnt`, `psgCnt` | 구간 출발 운항편수·출발 여객수 |
| `yesterdayFltDiffCnt`, `yesterdayPsgDiffCnt` | 전일 같은 구간 대비 증감 |

세 구간의 시작은 항상 60분 간격이고, 길이는 요청 `intrvlMin`(화면은 60분)을 따른다.
시작이 조회일 24시 이상인 항목은 응답에서 제외하며, 화면은 다음 날 시각과 `-`를 표시한다.
예를 들어 22:10 조회는 22:10~23:10, 23:10~24:00만 집계하고 +2시간은 다음 날 00:10로 표시한다.
자정 이후를 같은 날 00시 데이터로 순환 집계하지 않는다.
운항 원천 조회는 기존 `retrieveFltSmry` SQL을 각 구간과 전일 같은 구간에 재사용한다.

## 요약정보 (2026-11-01)

`.sum-info`는 아래 `smry*` 필드를 읽는다. 요청에 `category`를 더했고, 대상은 Prime Time 선택(`category`)을 따른다.
이전 요약정보 필드 `intrvlMaxWtngPsgCnt` · `intrvlAvgWtngSec` · `intrvlPrcsPsgCnt` · `cgnWtngSec`와
그 원천 SQL `CastDsbdMapper.retrieveRsltByIntrvl`(`DsbdIntrvlRawDto`)은 같은 날 삭제했다.

| category | 대상(왼쪽 라벨) | 시설 |
|---|---|---|
| `PSG` · `FLT` | 랜드사이드 | 아일랜드 + 출국장 |
| `CHKN` | 아일랜드 | 체크인 아일랜드 전체 (유인 카운터 `CC` 공용 Queue) |
| `DEP` | 출국장 | 출국장 전체 (`LGT`) |

원천은 시설 카드와 같은 10분 대기 결과(`FcltWtngDay`, `TN_PM_SMLT_FCLT_WTNG_RSLT`)다.
구간은 `[hhmm, hhmm+intrvlMin)`이고 24시에서 자른다. `intrvlMin`은 10분 단위여야 한다.

| 필드 | 화면 라벨 | 계산 |
|---|---|---|
| `smryWtngPsgCnt` | 전체 대기인원 | 조회 시각 `hhmm`의 대기인원 합 (`[hhmm−10, hhmm)` 행의 종료 대기) |
| `smryAvgWtngSec` | 평균 대기시간 | 구간 처리 여객의 처리인원 가중평균 (초) |
| `smryArvlPsgCnt` | 시간당 유입인원 | 구간 10분 행 유입 합. 유입 = 종료 대기 − 시작 대기 + 처리 (음수는 0) |
| `smryPrcsPsgCnt` | 시간당 처리인원 | 구간 처리인원 합 |

랜드사이드는 여객 한 명이 체크인과 출국장을 모두 지나므로 **진입·진출 기준**으로 합친다.

- 대기인원 = 아일랜드 + 출국장
- 평균 대기시간 = 아일랜드 평균 + 출국장 평균 (여객 1인이 겪는 총 대기). 한쪽만 산정되면 그 값을 쓴다
- 유입 = 아일랜드 유입 (랜드사이드 진입)
- 처리 = 출국장 처리 (랜드사이드 진출)

처리 여객이 0명이거나 대기시간이 빠진 처리 여객이 있으면 평균 대기시간은 `null`이다.

조회 결과가 없으면 각 지표는 `null`이고 화면은 `-`를 표시한다.
관측된 대기·처리인원 0명은 0으로 표시한다.
화면은 초 단위 원값을 분 단위 정수로 반올림한다.

프런트 목업도 조회 구간으로 요약정보를 계산한다. 목업의 시간별 곡선은 겹치는 분만큼 비례 배분한다.

맵형태보기의 상단 혼잡 알림에도 랜드사이드 요약정보 4개를 표시한다.
`SmltMapSlotDto.landsideSmry`는 위 `smry*` 필드 4개를 담으며, 슬롯 시각부터 60분을 같은 방식으로 계산한다.
대기·대기시간의 랜드사이드 합산은 `FcltWtngIntrvl.landsideOf`를, 숫자·분 표시는 공통 `toSummaryInfo`를 사용한다.
23:30 슬롯은 24:00까지 집계한다. 24:00 슬롯은 종료 대기인원만 표시하고 구간 지표는 `null`이다.
타임라인 이동·재생은 하루치 슬롯에서 값을 읽으며 추가 API를 호출하지 않는다.

Java는 참조 사본이므로 실제 백엔드에 DTO·서비스·Mapper 변경을 함께 반영하고 빌드·Oracle 조회를 검증해야 한다.

검증 명령:

- `cd react` 후 `npm run verify:dsbd`: 목업·화면 변환, 시간 변경, Prime Time 대상, 랜드사이드 합산, 미관측·0명, 자정 종료.
